# Q2 求解界限与字典序修改说明

## 1. 本次实际重算结果

| 候选主问题 | 服务序列 | 路线变体 | 兼容分配 | 当前一级解/min | 对偶下界/min | MIP Gap | 是否采用 |
|---|---:|---:|---:|---:|---:|---:|---|
| 双设施候选池 | 357 | 3116 | 23251 | **19736** | 16296 | 17.430% | 是 |
| 三设施候选池 | 437 | 3799 | 31330 | 20222 | 15950 | 21.126% | 否 |

最终双设施方案运输4000人，共107架次，人员总在途时间270734 min，燃油152910.4 kg，座位利用率81.830%，独立Validator为零违规。

MIP Gap按 `(incumbent-dual_bound)/abs(incumbent)` 计算。这里的对偶下界只针对有限候选路线主问题，不能作为原始无限路线模型的全局理论下界。

## 2. 字典序实现

程序采用两阶段实现：

1. 第一阶段只最小化总飞机使用时间，在300 s总时限的65%内记录当前最好整数解、对偶下界和MIP Gap；
2. 固定第一阶段当前最好值，用由可行域上界自动推导的支配权重依次优化人员在途时间、架次数和燃油。权重不是人工调参值；座位利用率仅在完整方案前四项相同时比较。

由于两个阶段均可能达到时限，论文使用“给定时限下的词典序最好可行解”，不使用“全局最优解”表述。

## 3. 三设施扩展的正确解释

三设施候选池包含双设施候选池，因此其数学最优值不可能更差。三设施模型的对偶下界由16296降至15950 min也说明可行域确实放宽；但模型规模增加后，求解器在相同300 s内只找到20222 min的整数解，没有重新找到已知19736 min解。因此程序通过历史最优保留继续采用双设施方案。这是有限时间求解现象，不能得出“三设施路线无效”的结论。

## 4. 复现命令

在 `code` 目录执行：

```powershell
python scripts/05_solve_q2.py --run-id q2-pair-bound --variant-cache outputs/q2/pair_n3_h10.pkl --skip-separate --time-limit 300 --mip-gap 0
```

再以前一步生成的路线作为历史最好解执行三设施扩展：

```powershell
python scripts/05_solve_q2.py --run-id q2-triple-bound --variant-cache outputs/q2/pair_n3_h10.pkl --skip-separate --initial-q2-routes outputs/q2/runs/q2-pair-bound/q2-pair-routes.csv --initial-q2-assignments outputs/q2/runs/q2-pair-bound/q2-pair-assignments.csv --triple-limit 80 --time-limit 300 --mip-gap 0
```

关键输出为：

- `q2-routes.csv`、`q2-assignments.csv`：最终可提交方案；
- `q2-validator.json`：独立校验结果；
- `q2-bounds.json`：当前运行的整数解、对偶下界、MIP Gap和求解状态；
- `run_config.json`：候选规模、时限和完整求解诊断；
- `q2-bound-comparison.json`：本次双设施与三设施结果的汇总。
